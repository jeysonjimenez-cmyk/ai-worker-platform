T4.5.2
SDK Python mínimo: create_job + wait + download
Paquete ai-platform-client con los tres métodos del contrato. Backoff exponencial en wait(). Streaming sin buffer en download(). Una sola dependencia de producción: httpx.
Desarrollo 3 h
✅ 2026-06-15
▼

El problema que resuelve: Video Crack necesita integrarse con la plataforma sin implementar el protocolo HTTP+polling a mano. El SDK encapsula los tres pasos del ciclo (crear → esperar → descargar) con las decisiones correctas de backoff, timeout y streaming — criterio: lo mínimo que Video Crack usa hoy, nada más.

Archivos creados
  • client/pyproject.toml NEW— Paquete ai-platform-client (Python 3.12 + uv). Única dependencia de producción: httpx>=0.28.0.
  • client/uv.lock NEW— Versiones congeladas: httpx 0.28.x + 14 dependencias transitivas.
  • client/ai_platform_client/__init__.py NEW— Exporta Client y JobTimeoutError.
  • client/ai_platform_client/client.py NEW— Client(base_url, app_key) con los tres métodos: create_job() (envía X-App-Key, mapea prioridad), wait() (backoff 2→4→8…tope 30s, corte por deadline, lanza JobTimeoutError), download() (streaming con httpx.stream(), sin buffer en memoria, lanza RuntimeError en 503).
Solo tres métodos públicos (criterio R5)

El SDK expone exactamente lo que Video Crack usa hoy. No hay cuarto método, no hay paginación de jobs, no hay cancelación — eso se añade cuando haya un segundo cliente que lo necesite. Tres métodos similares no justifican una abstracción mayor.

download() con timeout=None en el stream

Un VTT de 4.2 h puede tomar segundos en descargarse. Un timeout fijo de red cortaría descargas legítimas. timeout=None en el stream es la decisión correcta para archivos de tamaño variable; el timeout de "job completo" ya lo maneja wait().

Servidor HTTP de stdlib para el test 503

Un http.server.HTTPServer en un thread de stdlib es un servidor HTTP real, no un mock de librería. El SDK ve un 503 genuino desde un socket TCP real. Esto es coherente con la postura "sin mocks" del proyecto y no añade dependencias de testing.

Modo both: errores no bloquean el pipeline

Si PUBLIC_BASE_URL/PLATFORM_API_URL/PLATFORM_APP_KEY no están configuradas, el job corre solo en legacy sin error — el background job simplemente no se lanza. Esto permite desplegar sin configurar la plataforma primero, y garantiza que un fallo de la plataforma no bloquea al usuario.

El audio endpoint no requiere que el job esté en done

El audio puede servirse en cuanto está descargado (paso 1 del pipeline de Video Crack). El worker de la plataforma llama al endpoint durante el paso 2 de transcripción — no hay carrera de condición porque el archivo ya existe en disco.

T4.5.6
Comparador de salidas (transcript viejo vs plataforma)
compare_vtt_files(): similitud via difflib.SequenceMatcher + análisis de timing. Veredicto automático: PARIDAD_ACEPTABLE (≥85%), REVISAR (≥70%), REGRESION (<70%). CLI con exit code 1 si no es paridad.
Desarrollo · Video Crack 3 h
✅ 2026-06-15
▼

El problema que resuelve: comparar dos VTTs de transcripción a ojo es imposible para audios de horas. La herramienta cuantifica la similitud de texto (ignorando puntuación) y el alineamiento de timing, y emite un veredicto binario que puede usarse como criterio de aceptación automatizable.

Archivos creados
  • ../video-crack/scripts/compare_transcripts.py NEW— compare_vtt_files(vtt_a, vtt_b, *, lang_a, lang_b) → dict: similitud de texto via difflib.SequenceMatcher (texto normalizado: minúsculas, sin puntuación), alineamiento de timing (±1s de tolerancia), veredicto automático. format_report(result) → str: salida legible, tope de 20 bloques de diferencia. CLI: python scripts/compare_transcripts.py <job_id> o --vtt-a/--vtt-b. Flag --json. Exit code 1 si no es PARIDAD_ACEPTABLE.
Archivos modificados
  • ../video-crack/backend/routers/tradu.py— _submit_platform_background() guarda platform_lang.txt cuando la plataforma detecta idioma. GET /tradu/jobs/{id}/compare: retorna resultado JSON + campo report listo para mostrar. 404 si falta cualquiera de los dos VTTs.
_normalize() elimina puntuación antes de comparar

Los dos modelos de Whisper (local vs plataforma) producen puntuación distinta para el mismo audio. Sin normalización, diferencias tipográficas ("¿Hola?" vs "hola") inflan la divergencia. El veredicto se basa en el texto, no en el formateo.

pg_notify al re-encolar via SQL

La cancelación via API dispara el webhook y libera VRAM en jobs running; el UPDATE SQL directo no hace ninguna de las dos. Al re-encolar via SQL, pg_notify('jobs_channel', job_id) es necesario para que los workers descubran el nuevo pending sin esperar el siguiente poll — sin la notificación, el job puede esperar hasta 30s innecesariamente.

Retrospectiva — aprendizajes clave

Lo que funcionó bien

  • SDK de 3 métodos + 1 dependencia: integración completa sin complejidad innecesaria
  • Flag de tres posiciones: both permite validar en producción sin riesgo para el usuario
  • comparar_transcripts.py: veredicto automático ahorró revisar 57k palabras a mano
  • Modo both fire-and-forget: errores de plataforma no bloquean el pipeline de Video Crack
  • Reuse del escape hatch SSRF: quitarlo del env de producción es un cambio operacional, no de código

Lo que aprendimos del sistema real

  • VRAM subió 393 MiB sobre F4: audio en inglés con contenido denso es más pesado
  • El margen de 440 MiB es ajustado — monitorear con audios futuros
  • Reiniciar el backend al desplegar nuevos endpoints es un paso que debe estar en el runbook
  • Similitud mínima del corpus: 90.5% con puntuación normalizada — un umbral de 85% es razonable
  • Requeue en 54s con heartbeat de 90s: el monitor tiene latencia real (hasta 30s adicionales sobre el timeout)

Lo más difícil técnicamente

  • audio_url https:// público: Video Crack necesita exponer su audio hacia internet para que el worker lo descargue
  • Thread daemon fire-and-forget con errores silenciosos: encontrar el balance entre no bloquear y no perder contexto
  • wait() con backoff exponencial: tope en 30s para no dejar intervalos de polling demasiado largos en jobs lentos
  • Similitud de texto con modelos diferentes: los dos Whisper producen puntuación distinta para el mismo audio

Postura de producción al cerrar F4.5

  • ALLOW_HTTP_AUDIO removido de ~/.config/ai-platform/worker-whisper.env en ialab
  • App key video-crack activa en DB del VPS
  • SSRF estricto verificado en producción (Escenario 0 del e2e)
  • VRAM pico calibrado: 5060 MiB (margen 440 MiB sobre MIN_VRAM=5500)
  • Runbook SQL para operar sin dashboard (docs/RUNBOOKS/f4.5-ops-without-dashboard.md)
