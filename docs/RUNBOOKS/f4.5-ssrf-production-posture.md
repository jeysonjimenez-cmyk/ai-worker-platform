# Runbook — Postura SSRF del worker en producción

> Aplica a: `worker-whisper` en ialab.
> Estado desde T4.5.7: SSRF estricto — `ALLOW_HTTP_AUDIO` **no** está en el env de producción.

---

## Postura actual

| Variable | Valor en producción | Efecto |
|---|---|---|
| `ALLOW_HTTP_AUDIO` | **no configurada** | SSRF activo: solo `https://` público, sin IPs privadas/Tailscale/loopback |

El worker rechaza cualquier `audio_url` que no sea `https://` y cuya resolución DNS devuelva una IP en:
- RFC 1918: `10/8`, `172.16/12`, `192.168/16`
- Loopback: `127/8`, `::1`
- Link-local: `169.254/16`
- Tailscale: `100.64.0.0/10`

El cliente (Video Crack) debe entregar `audio_url` como URL `https://` pública. Ver `docs/SDK.md` §Restricciones.

---

## Procedimiento: remover `ALLOW_HTTP_AUDIO` de ialab

Este procedimiento se ejecuta una sola vez al pasar de testing (F4 e2e) a producción (F4.5).

```bash
# 1. Conectar a ialab
ssh ubuntu@<tailscale-ip-ialab>

# 2. Editar el env del worker — quitar la línea ALLOW_HTTP_AUDIO
sudo nano /etc/ai-platform/worker-whisper.env
# Eliminar o comentar: ALLOW_HTTP_AUDIO=true

# 3. Verificar que ya no está
sudo grep -i ALLOW_HTTP_AUDIO /etc/ai-platform/worker-whisper.env
# → debe devolver vacío (sin resultados)

# 4. Reiniciar el worker para que tome el nuevo env
sudo systemctl restart worker-whisper

# 5. Verificar que el worker arrancó
sudo systemctl status worker-whisper
```

## Verificar que el SSRF rechaza URLs no permitidas

Desde el VPS (o cualquier máquina con `X-Worker-Key` válida), crear un job con una URL prohibida
y confirmar que falla:

```bash
APP_KEY="ak-<key-de-video-crack>"
API="http://100.106.192.45:8081"

# http:// → debe recibir job en error con mensaje SSRF
curl -s "$API/ai/jobs" \
  -H "X-App-Key: $APP_KEY" \
  -H "Content-Type: application/json" \
  -d '{"service":"transcription","payload":{"audio_url":"http://example.com/audio.mp3"}}'
# → job creado; al procesarlo el worker lo marca error con SSRFError

# Consultar el error del job
JOB_ID="<id devuelto arriba>"
curl -s "$API/ai/jobs/$JOB_ID" | jq '.error'
# → "audio_url must use https, got scheme=\"http\""
```

El error debe contener `must use https` o `blocked IP` — la misma cadena que lanzan los tests unitarios.
