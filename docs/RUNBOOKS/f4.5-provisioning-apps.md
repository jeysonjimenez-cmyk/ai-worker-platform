# Runbook — Alta de apps en la plataforma

> Aplica a: toda app que quiera crear jobs vía `POST /ai/jobs` con `X-App-Key`.
> No existe endpoint de admin para esto; el alta es siempre vía `INSERT` SQL directo en PostgreSQL.

---

## Procedimiento estándar

### 1. Generar la app key ✅ 2026-06-16

La key debe ser impredecible. Formato sugerido: `ak-` + 40 hex chars:

```bash
# En cualquier máquina con openssl
openssl rand -hex 20 | awk '{print "ak-" $1}'
# ejemplo: ak-3f8a2b7c1d9e4f0a6b5c2d8e1f7a3b4c9d0e5f6a
```

Guardar la key en el secreto operativo del equipo **antes** de ejecutar el INSERT. No se puede recuperar después (la DB solo la guarda, no la expone de vuelta).

### 2. Ejecutar el INSERT en el VPS ✅ 2026-06-16

```bash
# Conectar al PostgreSQL del VPS
# Contenedor real: vps-postgres-1 · usuario: aiworker · db: aiworker
ssh ubuntu@100.106.192.45
docker exec -it vps-postgres-1 psql -U aiworker -d aiworker
```

```sql
-- Alta de la app
INSERT INTO apps (id, name, api_key, max_daily_usd, active)
VALUES (
    'video-crack',                         -- id único de la app (slug)
    'Video Crack',                         -- nombre legible
    'ak-<key-generada-en-paso-1>',         -- key real (no commitear)
    100.00,                                -- budget placeholder; enforcement en F9
    true
);
```

> `max_daily_usd` se persiste ahora pero no se aplica hasta F9. Usar un valor razonable como placeholder.

### 3. Verificar que la key funciona ✅ 2026-06-16

```bash
# Desde el VPS o cualquier máquina con acceso (ajustar HOST si es Tailscale)
APP_KEY="ak-<key-generada>"
API="http://100.106.192.45:8081"

# Debe devolver 201 con un job_id
curl -s -o /dev/null -w "%{http_code}" "$API/ai/jobs" \
  -H "X-App-Key: $APP_KEY" \
  -H "Content-Type: application/json" \
  -d '{"service":"transcription","payload":{"audio_url":"https://example.com/audio.mp3"}}'
# → 201

# Con key inválida → 401
curl -s -o /dev/null -w "%{http_code}" "$API/ai/jobs" \
  -H "X-App-Key: ak-invalida" \
  -H "Content-Type: application/json" \
  -d '{"service":"transcription","payload":{}}'
# → 401
```

### 4. Deshabilitar una app (revocar acceso)

```sql
UPDATE apps SET active = false WHERE id = 'video-crack';
```

No se elimina la fila; `active = false` revoca el acceso inmediatamente sin perder el historial de jobs.

## Seguridad

- La key de producción **no se commitea al repo**. Vive en el gestor de secretos del equipo.
- La key del e2e de F4 es distinta de la de producción (se generó para pruebas y puede rotarse independientemente).
- Para rotar una key: generar nueva key → UPDATE en DB → comunicar la nueva key a la app → invalidar la vieja.

```sql
UPDATE apps SET api_key = 'ak-<nueva-key>' WHERE id = 'video-crack';
```
